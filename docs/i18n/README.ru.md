Windows App — клиент, Microsoft Dev Box — хост, либо другая среда Windows RDP: сохраните щелчки, ввод и снимки агента computer-use после обнаружения отключения; перестаньте следить за подключённым окном (сворачивание требует проверенной совместимой отрисовки); используйте сеанс с выполненным входом без хранения паролей или автоматического входа.

Консоль остаётся разблокированной; соблюдайте правила. Сворачивание Windows Sandbox не проверено.

<img src="../../assets/keep-desktop-interactive.png" width="700" alt="До и после отключения RDP или сворачивания: приложения работают, но щелчки, ввод и снимки могут перестать работать; передача на консоль и совместимый клиент помогают.">

- **Сохраните ввод агента после отключения:** щелчки, ввод и снимки остаются доступны на существующем рабочем столе после обнаружения отключения RDP системой Windows; обнаружение потери сети может занять время.
- **Не следите постоянно за подключённым окном:** отойдите от удалённого окна; сворачивание требует совместимой отрисовки и отдельного успешного теста ввода в вашей среде. Клиент должен продолжать отрисовку удалённого рабочего стола при свёрнутом окне; отдельно проверьте щелчки, ввод и снимки.
- **Используйте сеанс, в который уже выполнен вход:** сохраните сеанс и приложения без хранения паролей или автоматического входа; инструмент не выполняет вход после перезагрузки.

Концепция с английскими подписями, не живой тест. Поддержка клиента и локальная блокировка, когда ноутбук не находится в режиме сна, зависят от условий.

> **Передача оставляет удалённый рабочий стол разблокированным.** Тот, кто может управлять физической или интерактивной консолью ВМ, может использовать сеанс без входа в Windows. Не используйте доступный другим общий ПК или недоверенную консоль. Нет автоматизации за блокировкой или обхода правил. [Настройка и риски доступа](../configuration.md).

Только если правила разрешают настройку передачи RDP/консоли; проверьте свою среду, без общей сертификации Dev Box.

**[Windows Sandbox](https://learn.microsoft.com/en-us/windows/security/application-security/application-isolation/windows-sandbox/) — свёрнутое окно; НЕ ПРОВЕРЕННЫЙ кандидат:** Когда окно Windows Sandbox на хосте свёрнуто, а гостевая система и приложения продолжают работать, сохраняются ли щелчки, ввод и снимки экрана? Развёртывание и непрерывность ввода не проверены; работа инструмента с отрисовкой клиента или передачей гостевой системы неизвестна и требует отдельной проверки, это не готовое проверенное решение.

## Windows App / RDP

Установленная диагностика пытается выполнить щелчки, ввод и снимок примерно через 10 секунд после каждого отключения RDP настроенного пользователя, включая обычную работу, и может мешать агенту. Отдельный документированный флаг запуска для её отключения отсутствует; удаление хоста убирает и передачу.

Маршрут Windows App/RDP: отключение использует передачу хоста; свёрнутое окно — совместимую отрисовку и настройку хоста. Сохраните проверенную настройку двух ПК и проверяйте каждый режим. Нет интеграции/запуска агентов, сохранения паролей или автоматического входа. [→](../configuration.md#mode-choice)

Сопровождающий сообщает успех локальной блокировки только для проверенной пары с ноутбуком не в режиме сна и настроенным клиентом, не удалённой блокировки; крышка/сеть требуют обнаружения отключения Windows.

## Windows Sandbox — UNVALIDATED

Sandbox — предложенный эксперимент: остановитесь, если разрешённый рабочий способ установки/проверки не установлен. Запишите щелчки, ввод и снимок без секретов в видимом окне; сверните на записанный интервал при работающих госте/приложениях, повторите ввод и новый снимок, восстановите и проверьте. Не проверено; при сбое оставьте окно видимым. Шаги RDP для двух ПК, отключения и закрытия/открытия не являются процедурой Sandbox. [→](../configuration.md#sandbox-minimized-window-experiment)

<a id="setup"></a>

До установки: хост включён, не спит и разблокирован; правила разрешают такое использование. Требования Windows, администратор, Git, PowerShell 5.1 и VBScript ниже.

## Два компьютера

Удалённый хост — ПК/ВМ Windows, где выполняется автоматизация; локальный клиент — ПК Windows с RDP/Windows App. Нужны Windows PowerShell 5.1, VBScript и Git для клонирования. Установка на хосте требует одобрения администратора. На обоих компьютерах получите новую доверенную копию в личной папке текущего пользователя, а не в общей папке с правом записи.

<details>
<summary>Windows App / Microsoft Dev Box / Hyper-V</summary>

> **Windows App — клиент подключения, Microsoft Dev Box — управляемая облачная рабочая станция. Риск связан с чужим доступом к разблокированной консоли, а не с небезопасностью самого продукта. Управляемый хост одного разработчика без интерактивного доступа к консоли для недоверенных лиц менее рискован, чем общий ПК. Не предполагайте, что Microsoft Dev Box предоставляет такой доступ. Соблюдайте правила организации: это не автоматизация за заблокированным удалённым экраном и не обход политики блокировки.**

</details>


```powershell
git clone https://github.com/yeelam-gordon/KeepDesktopInteractive.git "$env:LOCALAPPDATA\KeepDesktopInteractiveSource"
Set-Location "$env:LOCALAPPDATA\KeepDesktopInteractiveSource"
```

Откройте клонированную папку на каждом компьютере и выполняйте команды из неё. Первую команду запускают на удалённом хосте с одобрением повышения прав, вторую — на локальном клиенте.

```powershell
wscript.exe .\start-desktop-session-setup.vbs
```

```powershell
wscript.exe .\set-local-rdp-minimize-rendering.vbs
```

Полностью закройте удалённый клиент, откройте его снова и подключитесь. [Результаты установки](../configuration.md#quick-setup): на хосте `Installed: true` и `Status: Ready`, на клиенте `Succeeded: true`.

<a id="proof"></a>

- После обнаружения отключения RDP системой Windows существующий сеанс передаётся на консоль для сохранения ввода GUI.
- Настройка отрисовки помогает совместимым клиентам при свёрнутом окне; проверяйте отдельно.
- Проверьте реальные щелчки, ввод и снимки по конфиденциальным результатам нужного режима, а не только работающие приложения.

До теста запишите время начала, остановите другую UI-автоматизацию, сохраните важную работу и уберите конфиденциальные окна; отключение запускает диагностику. Нужны изменение файла после начала и правильные Passed/Mode; затем безопасная задача щелчка/ввода/снимка при итоговом разрешении консоли. Диагностика не доказывает работу всех приложений. [→](../configuration.md#reported-compatibility-evidence)

## Первая проверка

Обычным способом отключите RDP, подождите 30 секунд и подключитесь снова; диагностика запускается автоматически. Для отдельной проверки свёрнутого окна выполните команду ниже на удалённом хосте, сразу сверните окно клиента на 90 секунд, затем восстановите его. Проверка ждёт 60 секунд перед реальным вводом и захватом экрана.

```powershell
wscript.exe .\test-interactive-desktop-automation.vbs --minimized-test
```

На хосте откройте новый `%LOCALAPPDATA%\KeepDesktopInteractive\desktop-proof.json`. Ниже приведены ожидаемые поля для каждой проверки, а не результаты измерений в ходе этого обновления:

```json
{ "Passed": true, "Mode": "AfterDisconnect" }
```

```json
{ "Passed": true, "Mode": "WhileClientMinimized" }
```

Проверка свёрнутого окна действительна только если оно оставалось свёрнутым во время ввода и захвата экрана; хост не может наблюдать состояние клиента. Не публикуйте журналы и снимки: они могут содержать соседние области рабочего стола. [Подробности проверки](../configuration.md#verify-on-each-new-machine).

## Ограничения

Настройка описана для классического Remote Desktop Connection; поддержка Windows App зависит от версии. По сообщению сопровождающего, исходная пара клиент/хост прошла проверку свёрнутого окна до усиления защиты, но после развёртывания её не перепроверяли. Это не подтверждает поддержку всех клиентов. После перезагрузки войдите и разблокируйте сеанс один раз, затем запустите приложения и автоматизацию. Рабочие столы без графического интерфейса не поддерживаются. Удалённая блокировка, сон, выключение и выход из учётной записи могут остановить автоматизацию. [Все ограничения](../configuration.md#requirements-and-limitations).

При `Passed: false` прочитайте `Error`, `Stage` и журналы. Если результат отсутствует или устарел, проверьте установку и повторите тест. Если клиент не поддерживает свёрнутое окно, оставьте его видимым или используйте отдельно проверенный сценарий отключения. [Устранение неполадок](../../README.md#if-the-proof-fails) · [Проверки конфигурации](../configuration.md#configuration-checks).

<a id="undo"></a>

Удаление задач/восстановление клиента не блокирует текущую консоль автоматически. Сохраните работу и завершите автоматизацию; вручную заблокируйте хост и проверьте требование входа либо намеренно выйдите из учётной записи для завершения приложений. Блокировка останавливает GUI-автоматизацию.

## Отмена настройки

Выполняйте из соответствующих клонированных папок. Первая команда удаляет запланированные задачи с удалённого хоста; вторая восстанавливает настройки клиента на том же локальном ПК под тем же пользователем.

```powershell
wscript.exe .\start-desktop-session-setup.vbs --uninstall
```

```powershell
wscript.exe .\set-local-rdp-minimize-rendering.vbs --restore
```

Сохраните клиентский `%LOCALAPPDATA%\KeepDesktopInteractive\local-rdp-minimize-backup.json`, пока восстановление может понадобиться. Операции независимы и не удаляют диагностические данные. [Отмена](../configuration.md#undo) · [Основное руководство на английском](../configuration.md) · [README на английском](../../README.md).

Обновляйте в новый частный каталог, не клонируйте в существующий непустой; сохраните старую копию и резервные данные до успешной настройки и проверки. [→](../configuration.md#updating-the-first-prototype)
